# Grill intent phase

<!-- doc-meta: owner=eng | last-reviewed=2026-08-16 -->

Socratic shaping when intent is fuzzy — **crystallization**, not resolution. Shared behavior → [dialogue-contract.md](https://raw.githubusercontent.com/csark0812/toolbox/main/.skeleton/references/dialogue-contract.md). Mid-turn asks → [ask.md](ask.md). After intent has shape, continue with [protocol.md](protocol.md) (design tree) or exit.

## Core moves

1. **Listen first** — incomplete input is normal.
2. **Ask via [ask.md](ask.md)** — 1–3 same-branch lettered questions. The ask block (Questions only; self-contained stems) stands alone across hop sessions.
3. **Reflect before asking** — fold what you heard into the stem and options so the pick stands alone. Do not invent Context / Already agreed / Where/Deciding/Settled blocks. Do not restate the decision when the question stem already names it.
4. **Exhaust the branch** before you switch topics.
5. **Before crystallizing** — surface one tacit assumption or alternate frame. User gate unless skip ahead.
6. **Follow energy** — go where the user lights up.
7. **Stay in crystallization** — no solutions unless the user asks.
8. **Sharpen terms** against glossary — dialogue does not own glossary writes.

## Question cadence

Use [ask.md](ask.md). Prefer closed lettered picks. Free-text only when options cannot be named.

Avoid: steering "Why not just do Y?" outside the optional `> Why <letter>:` line. Avoid skill jargon in question stems.

## Exit

User accepts the crystallized statement, or is done for now. If a major thread is implicit, ask via [ask.md](ask.md) instead of closing.

## Output block

When exit criteria are met — not before.

```markdown
## Crystallized idea

[2–4 sentences from user's perspective]

## Alternate frame considered

- [chosen, discarded, or open]

## What remains open

- …
```
