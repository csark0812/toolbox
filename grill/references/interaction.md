# Grill interaction

<!-- doc-meta: owner=eng | last-reviewed=2026-09-01 -->

Use the lightest question form that can resolve the active branch.

## Ask an open question

Use a short open question when the user must define the outcome, boundary, priority, or acceptable tradeoff and honest options are not yet known.

Do not hide a preferred solution inside the question. Do not convert uncertainty into invented choices.

## Offer choices

Use a short list when the evidence reveals a small set of credible, distinct options.

- Explain the decision in plain language.
- Include only viable choices.
- Mark a recommendation only when evidence and known priorities support it.
- State the reason when it is not obvious.
- Allow another answer when the known set may be incomplete.

The list does not require fixed letters, headings, or a question template.

## Challenge a material choice

Before a consequential choice closes:

1. Test the strongest credible alternative or failure case.
2. Separate current evidence from assumptions.
3. Name evidence that would defeat or reopen the chosen approach.

A revisit trigger must work against the chosen approach. Evidence that only weakens a rejected option is not a revisit trigger.

## Continue a dialogue

- Carry forward accepted decisions and their reasons.
- Ask about the next unresolved dependency.
- Do not repeat a settled question for reassurance.
- Reopen a choice only when new evidence conflicts, a dependency changed, or the user asks.
- Keep implementation out of Grill. An explicit skip ends the dialogue and hands the agreed or user-selected direction to the next process.

## Avoid

- Long question inventories.
- Forced multiple choice for fuzzy intent.
- Recommendations before the user priorities or controlling evidence are known.
- Mandatory alternate frames for trivial choices.
- A revisit trigger for every minor decision.
- An exit summary that pretends unresolved material questions are settled.
