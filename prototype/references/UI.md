# UI branch

**Question:** "What should this look like?"

Generate several **radically different** UI variations for one surface. Stack-agnostic — use whatever the project already runs.

- Switchable variants (URL param, toggle, or tab bar) so the user can compare without redeploying.
- No design-system polish — rough is fine; learn layout and hierarchy.
- Surface full component/state after each interaction when state matters to the question.
- Do not invent a new top-level routing scheme — follow project conventions.
